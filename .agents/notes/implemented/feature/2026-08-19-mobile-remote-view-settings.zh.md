# Agent Note：带身份验证的手机远程查看本机设置

状态：已实现

[English](2026-08-19-mobile-remote-view-settings.md) | 中文

## 问题

只读手机页面原本只作为 Host 插件存在。用户无法在产品中找到或安全启用它，因为监听器依赖部署环境配置，访问令牌没有产品内设置流程，也没有本机界面报告手机可达地址或监听失败状态。

## 决策

`dsh-mobile-view` 拥有实时生效的 `mobile-view` 用户设置 namespace，其中包含 `enabled` 和 `port`。它串行执行监听器状态切换，在绑定端口前解析只写凭据，并通过仅回环可访问的状态投影发布请求状态、实际监听状态、检测到的外部 IPv4 地址和有限的失败码。只有用户明确启用后，独立监听器才绑定全部本机网卡，而且只暴露已有的只读页面与消息路由；其路由表不包含主 Web API 和状态投影。

`dsh-client-ui-settings-mobile-view` 贡献仅回环连接可见的设置分区。它通过现有 API 联合读取设置、凭据元数据和监听器状态，在浏览器中生成 256 位令牌，只写入而不读回已保存原值，并提供启用、关闭、端口、轮换和复制操作。监听器启动失败后，请求状态仍可关闭。API proxy 将 `mobile-view` 显式加入本地 Web 设置 allowlist；仅注册 namespace 仍不会使其暴露。Web 应用 profile 组合 Host 与浏览器插件；没有修改 vendored Cordis 源码。

## 考虑过的替代方案

未采用把主 Web 服务器暴露到局域网的方案，因为它会同时发布控制 API。未采用公网隧道，因为它会引入超出本地只读查看范围的外部账号、凭据和生命周期责任。未采用查询参数令牌和浏览器持久化令牌，因为 URL 与浏览器存储会扩大凭据留存范围。二维码生成暂缓，因为复制一个已报告地址和令牌已经完成首个可用路径，不需要新增渲染依赖。

## 结果

用户现在可以在“设置 → 远程查看”找到并操作该功能，无需编辑环境文件。手机需要能够访问一个已报告的局域网或私有组网地址，并在手机页面输入 Bearer Token。防火墙、私有组网成员管理、TLS、DNS、NAT 穿透和公网暴露仍属于部署责任。后续更新上游时，只需保留两个独立插件包及其 Web profile 行；`vendor/` 中不存在需要重新套用的补丁。
