# Agent Note: 一条命令完成 Web 验收

[English](2026-08-20-one-command-web-acceptance.md) | 中文

## 背景

完整的 AiDesktop Web 应用依赖有序生成的 Host、Client 与前端产物。源码 Host 和 Client 插件 watcher 分属不同进程，裸 Vite 页面缺少 `window.__DSH_BOOT__`，并不构成可用应用。功能会话需要一个可重复使用的入口，且该入口不能静默提供陈旧产物、接受无关 HTTP 监听方，或遗留任一长时间运行的进程。

## 决策

根命令 `accept:web` 负责本地 Web 验收编排。它会选择一个可用的环回端口，完成现有根构建，启动现有 Aistaff 源码 Profile 与 Client 插件 watcher，并等待所提供的 HTML 包含完整应用的启动数据，然后才把 URL 交给操作系统的默认浏览器。默认端口已被占用时，命令会保留占用方并向上选择下一个可用端口；显式端口是严格请求，不会自动替换。启动器保持前台运行，并在信号触发的清理期间等待两个自有运行时全部停止。

终端输出会把当前状态报告为构建中、启动中、已就绪、已停止或失败。启动器只在完整 HTML 检查成功后，随已就绪状态发布纯 HTTP 文本的 `Web 地址` 行，让终端能够链接该地址，同时避免把仅预留或启动失败的端口显示为可打开地址。

`accept:web:smoke` 使用完全相同的完整构建、Client watcher、源码 Host 与组装 HTML 就绪检查，成功后会立即停止自有进程，不打开浏览器，也不保持前台等待。它是供自动化使用的有界 Host 加 Client 集成检查。

报告只通过 `--report-dir <dir>` 显式启用。自有进程停止后，启动器会在该明确目录下写入 `accept-web-report.json` 与 `accept-web.log`，内容包括 commit SHA、工作树干净或未提交状态、已检查 URL、整体结果与稳定检查结论。它不会捕获子进程输出、环境变量值、凭据或提供方响应正文。报告只登记有意放进该明确目录的截图；普通运行不会向仓库写入报告或截图。

检出目录自有的 `scripts/aidesktop-accept` 入口通过自身真实路径解析仓库，并使用 pnpm 的显式工作目录选项调用根命令。用户可以在 `PATH` 中安装指向该入口的符号链接；全局安装项不包含复制的实现或固定仓库路径，检出目录被移动或删除后会明确失败。

完整构建是默认的新鲜度规则。该命令不会推断哪些文件发生了变更，也不提供跳过构建的模式，因为 Host 生成的 Remote 声明、Client bundle 与前端 shell 之间存在有序依赖。现有的双命令开发工作流仍可用于专门场景；直接启动 Vite 不属于验收路径。

## 影响

默认端口已被占用时，命令不会复用或停止占用方，而是在其他端口启动本次构建，因此并行验收不需要预先协调端口；自动顺延只适用于默认端口，显式端口冲突仍会失败。通过已安装入口调用时，该命令可在仓库根目录外运行。调用方可通过稳定标签区分进度、就绪、正常停止和失败，并且只有就绪运行才会输出可打开地址。启动器运行期间，Client 插件编辑会自动重新加载。Web shell、Host 约定或普通包发生变更后，需要重新启动该命令；命令会在重新打开应用前重建所有被消费的产物。浏览器交接失败时，已验证的 URL 仍会显示，供用户手动打开。

## 验证

聚焦测试覆盖参数校验、生命周期状态渲染、URL 发布、严格端口所有权、默认端口自动顺延、完整应用识别、不经 shell 的浏览器命令与无凭据报告序列化。`pnpm run accept:web:smoke -- --report-dir <external-dir>` 会在不进行付费模型调用的前提下，执行真实根构建、Aistaff 源码 Profile、Client watcher、HTTP 就绪检查、报告写入与信号清理路径。前台 `accept:web` 运行会额外覆盖浏览器交接。
