# Agent Note：模型目录不表示账户已获得访问权限

[English](2026-08-16-model-directory-and-access-failures.md) | 中文

状态：已实现

## 问题

与 OpenAI 兼容的 `GET /models` 响应会公布模型标识符，但并不保证当前账户已经启用每个模型，也不保证每个标识符都接受聊天请求。如果把每个新标识符都视为已选中，异构的图像、音频、嵌入以及受账户权限限制的产品都会进入对话模型目录。当提供方以 HTTP 400 报告产品尚未启用时，pi-ai 只暴露扁平化的错误文本，因此该请求原本会表现得像用户输入无效。

## 决策

端点探查仍是只读的目录操作，绝不执行隐藏的生成探测。选择器初始不勾选任何候选项，并明确说明启用状态和聊天支持均未验证。这样无需依赖模型名称的允许列表或拒绝列表，就能保留未来未知的聊天模型，同时要求用户明确选择后才更改配置。

pi-ai 流适配器只在错误文本明确表达产品或模型尚未启用时，才先于通用 HTTP 400 分类记录 `MODEL_ACCESS_DENIED`。客户端投影把这个稳定错误码映射为专门的模型访问类别，并引导用户启用模型或切换模型。同一提供方路由仍可供其他模型使用，而且重试策略不包含这个终止错误码。

## 已考虑的替代方案

我们否决了按 `image`、`audio`、`embedding` 或厂商命名惯例过滤标识符，因为名称不是能力元数据，新聊天模型可能被误分类。我们也否决了调用每个发现的模型，因为探测可能产生费用、触发提供方副作用、消耗速率限制，而且仍可能因与能力无关的原因失败。最后，我们否决了把模型启用问题归类为身份认证问题，因为同一凭据仍可能成功调用这条路由上的其他模型。

## 影响

获取大型提供方目录不会再静默填充对话选择器。用户选中尚未启用的模型时，会收到针对账户权限的恢复指引，而不是输入参数错误提示。通用发现仍不能证明聊天、工具或授权支持；如果提供方公开权威能力元数据，可以在独立变更中把它加入发现结果，而无需改变这个安全默认值。
