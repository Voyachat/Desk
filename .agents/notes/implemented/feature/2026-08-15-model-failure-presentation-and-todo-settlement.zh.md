# Agent Note：模型失败呈现与 todo 状态收敛采用安全投影

[English](2026-08-15-model-failure-presentation-and-todo-settlement.md) | 中文

状态：已实现

## 问题

提供方与 SDK 的失败消息可能包含原始响应体、端点查询参数或凭据。将这些消息直接渲染到对话或重试行，会把不可信诊断暴露为主要用户文案。失败轮次还会让最后的 todo 投影停留在 `pending` 或 `in_progress`，错误暗示模型请求已经终止后工作仍会继续。

## 决策

Client runtime 只从稳定的结构化字段投影每项持久模型失败。投影会分类已知错误码和 HTTP 状态，保留有效的提供方重试延迟，并用错误码、状态、重试延迟和请求标识符组装长度受限的诊断。提供方消息文本绝不会复制到显示事实或终端 `Turn Error` 节点。对话 UI 把类别本地化为可操作指引；安全诊断在终端失败行和自动重试行中都保留在默认关闭的披露区域内。

todo 工具保留对模型可见且持久化的 `pending`、`in_progress` 和 `completed` 状态。它的读取侧 Session 投影负责失败收敛：错误 `turn/end` 把 `in_progress` 映射为 `failed`，把 `pending` 映射为 `blocked`，并保留 `completed`。后续 `turn/start` 仍会清除上一份计划。UI 直接读取这些投影后的终止状态，不在本地推断轮次失败。

## 曾考虑的替代方案

在折叠披露区域内保留提供方原始文本的方案被否决，因为披露区域仍是用户可见界面，无法让凭据变得安全。基于消息子字符串分类失败的方案被否决，因为提供方措辞不稳定，而且消息本身可能包含敏感数据。在 `TodoPanel` 内收敛 todo 状态的方案被否决，因为其他投影消费者仍会保留错误的活跃状态。改写持久化 `todo/write` 事件的方案被否决，因为该事件记录的是模型在后续轮次失败之前提交的工具输入。

## 后果

提供方原始 JSON 和类凭据消息内容不再进入主要或诊断性对话文案。配额、速率限制、认证、网络、超时、提供方可用性、上下文窗口、无效请求、配置和未知失败会提供不同的恢复指引，同时不把失败归因于当前所选模型。轮次失败后，保留的任务面板不再包含运行中或待处理条目，也不会声称尚未启动的工作已经失败。
