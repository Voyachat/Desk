# Agent Note：聊天视图把轮次活动折叠为一行

[English](2026-08-17-chat-activity-fold.md) | 中文

状态：已实现

## 问题

较长的 agent 轮次会为每个推理块、每次工具调用和轮次中途叙述分别渲染一行，使对话记录看起来像执行日志。用户与主流聊天产品比较时，会看到几十行内部执行细节，而对话本应只显示问题、简洁的工作信号和答案。

## 决策

ChatView 在渲染前对可见流程分组。连续的可折叠 Node 合并为一个默认收起的 `ActivityFold` 披露行：全部完成后显示带耗时和根工具调用数量的 `已处理`，仍有成员运行时显示带实时时钟的 `正在处理`。展开后，原始节点恢复到摘要行下方的原位置。可折叠内容包括工具调用行、仅思考的 Assistant 步骤，以及轮次以带文本的收尾 Assistant 结束后的中途叙述。运行中的 `ask_user_question` 调用例外，因为此时需要读者行动，待回答问题必须在它接管的编辑器旁保持可见；回答后它与其他工具行一样折叠。最终答案、用户行、错误行和轮次页脚是分隔折叠序列的屏障。

分组依据 `order` 和从轮次尾部节点收集的结构性结束事实（每个轮次的 closing `finalNode.seq`）。唯一依赖内容的输入是 `chat.legacy.partial` 上的布尔选择器，用于判断流式步骤是否已经显示正文。运行中的 Assistant 步骤会在第一段正文到达的精确帧离开折叠，因此最终答案不会在收起行内流式输出，只有内容分片更新时也不会重新分组。运行中的折叠行取代基础轮次状态成为工作信号；基础状态继续覆盖还没有节点的首 token 等待。折叠行没有分页锚点，成员位置保留各自锚点；折叠身份为 `fold:<first member key>`，成员只在尾部增长，因此保持稳定。

## 已考虑的替代方案

我们否决了只分组连续思考和工具行、始终显示中途叙述，因为用户可见目标是主流产品每轮一行的形式，而一旦存在最终答案，中途叙述就是内部细节。我们否决了从 Chat snapshot builder 发布分组签名，因为结构性事实加一个布尔选择器已经覆盖所有分类变化，无需更改运行时约定。我们也否决了无条件折叠运行中的 Assistant 步骤，因为随后产生正文的步骤会在下一个结构事件之前不可见地流式输出。

## 影响

已完成轮次渲染为用户气泡、一个收起的活动行、最终答案和轮次页脚。运行中的轮次在叙述或答案开始流式输出时立即显示文本，并把所有思考和工具行保留在同一个动态行中；待回答问题保持在折叠外，读者无需展开即可作答。挂载真实聊天机制的工具展示验收会在断言前通过折叠自身的披露控件展开，而不操作成员行的控件。驱动折叠成员行的 Web e2e 使用共享 `expandActivityFolds` / `collapseActivityFolds` 辅助函数，并同步刷新相关 aria golden。已保存分页位置的锚点位于收起区域时，恢复会回退到第一个可见行。
