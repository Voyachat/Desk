# Agent Note：显式视觉路由为文本模型翻译浏览器图像

[English](2026-08-16-text-model-image-fallback.md) | 中文

状态：已实现

## 问题

浏览器图像准入曾把模型原生的图像能力视为完整产品能力。纯文本模型可以依据忠实的视觉描述完成用户任务，但 Host 会在形成任何持久提示词之前拒绝图像。把每条路由都标记为支持图像则会向不支持的提供方发送内容，在提供方拒绝后把图像块留在会话历史中，并错误描述模型目录。

## 决策

`ApiProxyService.imageFallback` 明确指定一个支持图像的提供方、模型和输出上限。该设置由部署方负责，因为启用后会把用户图像发送到该路由，并产生一次独立的提供方调用。缺少设置时继续严格拒绝；Host 绝不隐式发现或选择跨提供方回退。

当浏览器提示词所选模型明确不包含图像输入时，Host 先验证并存储图像，再要求配置路由按顺序返回可见证据、OCR、布局、代码、数字、不确定性和图像关系。提示词要求视觉模型把图像中的指令作为不可信内容报告，而不是执行。失败、截断、空响应、工具调用或其他非文本输出会在整个提示词进入 Agent 之前将其拒绝。

接受后的 `user/message.content` 包含原始用户文本、编号图像锚点和生成的描述，因此所选文本模型的输入持久且可回放，无需在请求时重写。同一消息源保留原始内容用于对话渲染、附件授权和会话日志媒体导出，并记录辅助路由归属与上报用量。模型切换只读取真实的模型可见文本，不会在翻译后保留虚假的图像要求。

AI Staff 将 `google/gemini-3.6-flash` 配置为回退模型，并明确声明其图像输入。该决策之前精确生成的 profile 会迁移到新 patch；用户编辑过的 profile 保持不变。

## 已考虑的替代方案

我们否决了默认声明未知模型或网关模型支持图像，因为一次误报就会让提供方在图像消息已经持久化后才拒绝。我们否决了自动选择第一个可用视觉模型，因为提供方顺序不是数据披露策略，可能未经部署方同意把图像发送到另一个提供方。我们也否决了只在 `agent/request` 重写请求，因为生成描述无法从会话日志重建，而直接压缩调用会绕过该扩展点。

## 影响

只要部署提供一条可用视觉路由，大多数文本模型就能完成浏览器图像任务；原生视觉模型继续使用直接路径和精确能力声明。回退会增加延迟、一次单独计费的模型请求，以及在压缩前保留于后续上下文的有损描述。`read_image` 工具输出和 subagent 延续仍使用各自的严格模态检查；把回退扩展到这些生产者需要单独的生命周期和展示决策。
