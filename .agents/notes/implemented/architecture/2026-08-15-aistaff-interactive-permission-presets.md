# Agent Note: AI Staff keeps approval interactive in every permission preset

Status: implemented

English | [中文](2026-08-15-aistaff-interactive-permission-presets.zh.md)

## Problem

AI Staff is a customer-facing desktop surface. The generic DSH base permits the explicit unattended `danger-full-access + never` combination, but applying that approval policy to the product's permission selector would suppress approval requests for operations that require explicit authorization. Product initialization must also preserve user-owned patch content and existing session history.

## Decision

The AI Staff profile overrides the generic DSH base so `read-only`, `workspace-write`, and `danger-full-access` all use the `ask` approval policy, with `workspace-write` as the default preset. Selecting `danger-full-access` changes the file sandbox only; it does not suppress approval requests for operations that require explicit authorization.

The generic DSH base retains `danger-full-access + never` for explicit unattended deployments. The product behavior is owned by `apps/aistaff-desktop/src/profile.ts`, not by the shared permission or approval services.

Profile initialization replaces only the two exact patch bodies previously generated by AI Staff. Any other `cordis.patch.yml` content is user-owned and remains unchanged. Existing sessions retain their logged `approval/policy` events; selecting a permission preset again appends the current interactive policy without rewriting history.

## Alternatives considered

**Inherit the generic `danger-full-access + never` preset.** That combination is retained for explicit unattended deployments, but it would make the customer-facing desktop suppress approval requests that require user authorization.

**Change the shared permission or approval services.** The behavior is specific to the AI Staff product profile, while shared deployments still need the existing unattended combination.

## Consequences

Every AI Staff permission preset remains interactive, while the file sandbox still follows the selected preset. Generic unattended deployments retain their existing behavior. Initialization preserves user-owned patches, and preset changes append permission history rather than rewriting it.
