# Agent Note：自动图片 fallback 路由

状态：已实现

[English](2026-08-19-automatic-image-fallback-routing.md) | 中文

## 问题

图片准入原先分散在浏览器 prompt 与 `read_image`。纯文本路由要么依赖前端专用配置，要么拒绝图片并要求用户切换模型。Vision MCP 无法修复这条准入边界，因为 MCP 执行依赖所选模型主动调用工具，粘贴的图片字节也可能根本不会到达 MCP 服务。产品还需要当前免费优先的策略，但不能把提供方价格当作永久承诺。

## 决策

`@voyaseek-ai/dsh-image-fallback` 拥有 `ctx.imageFallback`。浏览器 prompt 准入与 `read_image` 在所选路由未明确接受图片时调用同一服务。服务把持久图片引用发送到有序辅助视觉路由，再以带归因的文字分析替换图片并交给目标模型；原生支持图片的路由保持直传。浏览器上传的原始 block 保留在消息 source 元数据中，用于展示、授权和导出。

交付顺序是智谱 `glm-4.6v-flash`（`free`）、`glm-4.6v-flashx`（`paid-low`）、`glm-4.6v`（`paid-quality`），最后是 macOS 本机 OCR。提供方文档只说明第一条路由当前免费，不代表永久免费。只有可用性故障才升级到付费路由；认证和配置故障会停止托管升级，只允许使用本机 OCR。发生可用性故障的路由进入 60 秒进程内冷却。

用户已授权自动把图片传给智谱。部署仍要求单独保存 `ZHIPUAI_API_KEY`，仓库不内置也不写入凭据。AiStaff Desktop 从仅所有者可读的 `~/.codex/secrets/zhipu.env` 读取该值，并只通过 DSH 子进程环境传递，沿用 Gemini 与 DashScope 凭据的同一套文件校验。交付的智谱 profile 使用提供方的 `zai` 思考协议并默认关闭推理，让辅助描述和短 ping 把输出预算用于可见文本。`ping_image_fallback` 验证路由解析、声明的图片输入和最小提供方响应；除非 `include_paid` 明确允许，否则只探测免费路由。

## 结果

对话模型不再需要判断自己是否能查看图片，也不再要求用户切换模型。托管分析会增加一次单独计量的请求，且比原生视觉有损。价格、额度和模型可用性仍归提供方所有；路由标签是可编辑的部署策略，不是保证。健康状态有意只保存在进程内，因此重启会清除冷却，下一次请求或 ping 会重新检查提供方。

## 备选方案

未把智谱 Vision MCP 或社区 `cc-ds-glm-image-mcpServer` 作为主链路。它们适合显式工具调用，但不能拦截每个 prompt 或工具产生的图片，而且调用取决于模型的工具行为。也没有继续保留 Host 与文件系统两套实现，因为路由、付费升级和健康状态会发生漂移。
