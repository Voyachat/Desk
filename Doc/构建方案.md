## 1. 用户可见交付物

AiDesktop 是以可审计 Voyaseek Harness（下称 DSH）源码快照为底座的 Aistaff 桌面客户端。首个真实可验收纵向主干同时提供：可运行的 DSH Client、Aistaff 产品插件岛、服务端解析的 Workforce/Employee Bundle、云端 Activity、Material 展示，以及可操作的 Input/Approval/Receipt 用户流。默认 AI 员工 Runtime 在 Aistaff Cloud，客户端不复制 Run/Worker 状态机。

主干通过后再接入 `capability_only` 本地操作、`managed_runtime`、文件写入、渠道与发布更新。内部 Schema、迁移、测试或文档本身不替代可运行客户端。

## 2. 总体验收

- 从干净工作区安装、构建和启动，不依赖 `/Users/baron/projects/DsAgent`、`/Users/baron/projects/Aistaff` 或 `/Users/baron/projects/Aistaff-Client` 的本机路径。
- DSH 默认 Client 能创建并恢复本地 Session；Aistaff 插件在同一 Client chrome 中读取服务端已解析的 Workforce，不把本地 DSH Session 当作每个云端员工的运行前提。
- 用户选择员工后能提交一次输入，Cloud 以一个幂等操作创建 Activity，最终返回 inline 或文件 Material；客户端不接触内部 Session/Run/Attempt ID。
- Input/Approval 的回答到达真实 Cloud owner，Receipt 可读取；断线结果未知时能按原 operation 对账，无 owner 回执时不得显示成功。
- Employee Bundle 按 manifest/hash/signature 原子激活并上报 Receipt；服务端只能分配设备已声明支持的 Feature、capability 和 Runtime adapter。
- Renderer 无 Node 能力、Secret、客户绝对路径或设备私钥；无有效 Grant 时不能访问客户文件。
- Local 与 Managed Runtime 的进程、Home、凭据和 Bundle 相互隔离；任一任务、Profile 或插件都不能扩大 Locked Bundle。
- 云端 Employee、Run、Decision、Capability、Audit 仍由 Aistaff Cloud 权威解释；AiDesktop 不创建第二套云状态机或 Task Envelope。
- 桌面交付固定 `electron@42.7.0`，首个 macOS 安装包内置已部署的 DSH Runtime、Web 产物和生产依赖；目标机器不要求安装 Node、pnpm 或单独 DSH。

## 3. 不可破坏边界

1. DSH 通用 Core、Agent Loop 和 Client chrome 保持近上游；Aistaff 代码集中在 `apps/aistaff-*` 与 `packages/aistaff/**`，通过 slot、service seam 和 Host Port 接入。详见[架构](./架构.md)。
2. 实际执行 Runtime 拥有模型可见日志：Cloud 员工由 Aistaff Runtime 持有，客户端 DSH 只持有个人 Local/被分配执行的 Session；Aistaff Cloud 是企业事实源，Supervisor 是本机资源与副作用 owner。事实和本地副本分类见[数据](./数据.md)。
3. Renderer、Host、Supervisor、DSH Runtime 与 Cloud 之间只通过版本化窄端口通信；Cloud Client Gateway 的升级协商、幂等和事件恢复以 [API](./API.md#27-cloud-client-gateway-wire) 为唯一正文，现有 `desktop_protocol.v1`/`desktop_transport.v1` 不在本仓重定义。
4. 参考仓只提供权威合同或迁移依据，不形成构建、运行或发布依赖。
5. 当前 [`apps/frontend-demo`](../apps/frontend-demo/README.md) 是用户可见流程验证代码，不是正式 DSH Client、云端执行证据或权限实现。

## 5. 纵向阶段

### V0：验证已采用的 DSH 基线

交付：已从本地 DSH 工作区隔离复制源码，并以 `mode=source` 登记快照身份、MIT 许可证、排除项和更新策略；Keyless Web/Headless 基线已通过。

停止条件：adoption ledger、许可证或复制范围无法核对，或基线自身不能运行时，不开始产品移植。官方精确 SHA 可在后续升级时补强，不阻塞首个纵向代码。

### V1：云端 AI 员工用户主干

交付：工程 Desktop 启动 DSH Client；Aistaff 产品插件岛挂入上游 chrome；服务端通过 Client Gateway 下发已解析 Workforce/Employee Bundle；用户完成 `选择员工 → 提交输入 → Activity 状态 → Material → 必要 Input/Approval → Receipt → 断线恢复`。服务端核心 Runtime 全程在 Cloud。

范围：`client_mode: none`。先支持 text input、inline Material、一个文件 Material 和无本机副作用的 Interaction；本地资源 handle、客户文件访问、Runtime 下载和写入全部保持禁用。当前 Employee/Task/Approval/Receipt 内存实现只验证 UI/状态边界，必须由 Gateway adapter 替换后才构成真实 V1。

### V1D：macOS Electron 封装（Web V1 后的独立任务块）

交付：固定 `electron@42.7.0` 并使用 Electron Forge，把 Web 产物、生产依赖和平台匹配的 DSH Runtime 部署到安装资源；Electron Main 以受管子进程启动 Runtime。目标机器不需要外部 Node、pnpm 或 DSH，未随包提供的 Shell/编译器等系统工具不在承诺内，对应功能必须禁用或单独声明依赖。

首个本机验收只覆盖构建机原生 macOS 架构（当前为 `x86_64`）：从干净工作区生成 Forge `make` 安装产物，把产物移到仓外启动，完成 Keyless Session/流式输出/取消/Approval/重开，退出后确认端口与全部子进程释放，并检查产物无仓库路径、pnpm-store 路径、符号链接或缺失的 Runtime 文件。该本机产物可先使用受限 Loopback 且不得处理真实客户数据；签名、公证、自动更新和客户 IPC 载体仍按发布门槛验收。

### V2：`capability_only` 本地只读能力

交付：Cloud 下发已裁决的语义化 Local Operation；客户端完成系统目录选择器→Supervisor Opaque Grant/Attestation→一次受限文件读取→设备签名 Receipt→Cloud Material/Reconciliation。核心 Runtime 仍在 Cloud。

验收：无 Grant、过期/撤销/Revision 不匹配、越根、Symlink/重解析点逃逸均失败；Renderer、模型、日志和云回执不出现绝对路径。

### V3：`managed_runtime` 执行

交付：Managed Runtime 消费 Aistaff `desktop_protocol.v1` 请求，在 Capability/Decision/Lease/Fencing/Grant 交集内执行并返回设备签名 Receipt，支持重复请求、取消、崩溃恢复与 `unknown` 对账。

外部门槛：Cloud 的 Desktop Worker claim、设备身份、Artifact admission 与生产密钥链必须真实可用；Fixture 不构成完成证据。

### V4：受控写入与客户发布

交付：Diff 后逐次写入、签名安装/升级/回滚、目标平台加密与数据恢复。渠道、Marketplace、任意 Shell、多个可写根和第三方插件继续按独立切片后置。

## 6. 当前状态

已存在：AiDesktop 独立仓库、已隔离复制并登记来源的 DSH 源码快照、Aistaff Client slot 插件、本地 Fixture 投影/Remote/Bundle、真实 Host↔Client Web 主干，以及 Electron `42.7.0` 自包含 macOS x86_64 载体。Cloud 与 `capability_only` consumer conformance 已贯通正式 object layer、Remote 与 UI；真实 Rust control、加密持久 replay、Host process Provider 和 release sidecar 也已交付，但 sidecar 默认休眠且 production profile 不装载该链。当前 Fixture 覆盖 AI 员工导航、Approval Composer takeover、Receipt、对话/轨迹、详情和设置；其 Task Port 与 Store 不是正式 Cloud 状态边界。生产实现保留 Slot/props 交互，改用独立 `EmployeeExperiencePort` object layer，Store 不镜像业务 projection。

尚未闭合：Aistaff `packages/contracts/src` 与 API routes 尚无 Client Gateway contract artifact、`/api/client` endpoint、Projection/SSE replay 或 operation outcome owner；现有 Employee/Session/Run/Human Workbench/Deliverable 合同是服务端内部 owner DTO，不能替代 Renderer-safe Gateway。真实登录/Workforce、Run→Material 自动投影、签名 Employee Bundle 激活、设备身份/attestation、OS Secure Store data key、Cloud Receipt ack/reconciliation、客户数据保留策略和发布验收仍未闭合。任何 Demo Fixture、内存 Task 状态或 `localStorage` 都不得迁入正式数据层。

`V0`、V1 的 UI/slot/本地 Fixture Provider、真实 DSH Host↔Client Remote、Fixture Bundle、Electron `42.7.0` 自包含客户端，以及 artifact/transport 可注入的 `EmployeeExperiencePort` object layer、Cloud adapter、production/conformance bundles 和真实 DSH Web conformance 流程均已完成。V2 的 Local Consent/UI/Remote、SupervisorControl process Provider、Rust bounded read/list、加密 SQLite replay 和 dormant packaged sidecar 也已完成。production Cloud 或 Local bundle 只有在服务端按 [API](./API.md#27-cloud-client-gateway-wire) 发布并通过 conformance 的 artifact/endpoint、设备身份和 Receipt 对账机制到位后才可启用；当前固定 `test_only` 输入和显式 key Rust 黑盒不是 Aistaff 生产联调证据。短任务和当前状态见[实施任务索引](./tasks/README.md)。
