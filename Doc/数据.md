# AiDesktop 数据

> Owner：事实 owner、本地 SQLite、Projection/Outbox/Grant/Session Mapping、事务、Schema/迁移、保留、加密与恢复。
>
> 进程与权限 owner 见 [架构](./架构.md)；跨进程 DTO 见 [API](./API.md)；阶段见 [构建索引](./构建方案.md)。

## 1. 数据原则

1. 一个事实只有一个权威 owner。本地 Projection 允许过期和重建，但不能驱动 Cloud 状态机。
2. 模型可见内容以实际执行 Runtime 的权威日志为准：Cloud 员工由 Aistaff Runtime 持有，个人 Local 或受管 DSH 才由对应 DSH Session Log 持有；产品数据库不复制消息历史。
3. 真实路径、设备私钥、Token 和数据库密钥不进入 Renderer DTO、普通 SQLite 列、日志、Session Event 或 Cloud evidence。
4. Local 与 Managed 的 Session Store、Home、Credential Scope 和 execution workspace 分离；Managed 数据再按 tenant/device partition。
5. 跨进程操作使用 idempotency、revision 与恢复游标；SQLite 事务不能冒充跨进程分布式事务。

## 2. 事实 owner

| 事实 | 权威 owner | AiDesktop 本地持有 | 禁止 |
| --- | --- | --- | --- |
| Tenant/Workforce/Employee Bundle/Artifact/Run/Decision/Capability/Audit | Aistaff Cloud | 带 owner revision/ETag 的最小只读 Projection、已验证包缓存和待发送用户动作 | 在本地组合 Industry/Role 源配置、状态迁移替代 Cloud、复制 Task Envelope 状态机 |
| 模型输入、Tool call/result、Turn、模型可见 Approval/Receipt 引用 | 实际执行 Runtime：Cloud 模式为 Aistaff Runtime，受管/个人 DSH 为对应 Session Log | Renderer-safe Cloud 投影，或 DSH 自有持久化与 Client projection | Product DB 复制消息/event 正文、直接查询任一 Runtime 私有表 |
| 本地资源 Grant、真实路径、路径身份、实际副作用 | Supervisor | Grant ledger、claim、Receipt/evidence journal | Host/Renderer 保存绝对路径或自行裁决效果 |
| Engagement/Activity 投影、Bundle Activation、Cloud↔DSH 映射、UI 同步游标 | Product Host | 可重建 Projection、内容寻址包缓存和 Execution Mapping | 把映射 ID 当作任一上游实体、从本地缓存推导 Cloud active release |
| OIDC refresh token、设备私钥、数据库 master key | OS Secure Store，经 Host/Supervisor handle 使用 | 只保存 Opaque key handle | 普通 DB、argv、env、URL、日志、crash report |
| 用户草稿、菜单、面板、临时附件预览 | Renderer 内存 | 必需时仅保存明确的非敏感偏好 | 把 Demo `localStorage` 迁入正式事实层 |

## 3. SQLite 选择与数据库边界

V1 采用 SQLite 作为本地结构化存储，不采用 Aistaff-Client 的 WCDB Schema、ABI 或数据库文件。SQLite 是实现，不改变上述 owner：

| 逻辑存储 | 进程 owner | 内容 | 隔离 |
| --- | --- | --- | --- |
| `ProductStore` | Product Host | Cloud Projection、Workforce/Bundle Activation、Execution Mapping、用户动作 Outbox、Renderer-safe Grant projection | 本机个人功能与每个 Managed tenant 独立数据库/加密域 |
| `SupervisorStateStore` | Supervisor | Grant ledger、execution claim、Receipt/evidence journal、delivery state | Renderer/Host 不直接打开；按 device/tenant 分区 |
| DSH Session SQLite | 各 DSH Runtime | DSH 私有 Session header/events/projections | Local/Managed 独立 Home 和数据库；只由 DSH provider 打开 |

`ProductStore` 使用 Node 随产品可靠打包的 SQLite binding；`SupervisorStateStore` 使用 Rust 侧 SQLite adapter。具体 driver 不进入公共 DTO。WCDB 若未来被采用，只能替换对应 Store Port，使用新的独立文件和迁移计划；不得让 AiDesktop 与 Aistaff-Client 同时打开同一 WCDB/SQLite 文件，也不得暴露 WCDB 类型。

每个数据库只有 owner 进程写入。启用 `foreign_keys=ON`、`journal_mode=WAL` 和 effect-critical 数据的 durable sync；设置 bounded busy timeout，超时返回 `STORE_BUSY` 而不是无限等待。数据库目录仅 owner 可访问；SQLite 文件权限不能替代静态加密。

DSH 当前参考基线的 `SESSION_FORMAT_VERSION=0`，SQLite `SCHEMA_VERSION=15`，且不提供通用迁移或删除 API。AiDesktop 只把实际冻结值记录在发布兼容矩阵，不把数字复制成 Product Schema，不修改 DSH 表，也不从 Product migration 触碰 DSH 文件。

### 3.1 Electron 状态根

Main 在 Electron ready 和启动任何 Host/Runtime 前确定稳定的产品/渠道状态根；需要覆盖默认值时先调用 `app.setPath('userData', ...)`，此后只从 `app.getPath('userData')` 解析。安装资源 `process.resourcesPath` 永远只读。状态根内固定分区为 `product/`（ProductStore）、`supervisor/`（SupervisorStateStore 与 journal）、`dsh/local/`（Local `DSH_HOME`）和 `dsh/managed/<opaque_partition>/`（Managed `DSH_HOME`）。临时 staging/attachment 使用同一状态根下独立目录并受清理策略约束；真实 Secret 仍只在 OS Secure Store。

只有 Main/Supervisor 能解析这些目录并把 `DSH_HOME`/cwd 交给受管进程；Renderer DTO、Session Event、日志和 Cloud evidence 不含绝对路径。Electron single-instance lock 与各 Store owner lock 共同禁止第二个应用版本或 Runtime 并发打开相同数据库/Home；不同发布渠道必须使用不同状态根，不能以目录名共享凭据或 Session。

应用更新只原子替换只读安装资源并保留状态根。新版本先校验发布兼容元组，再由各 owner 完成迁移后启动 Runtime；失败保留旧数据并进入回滚/只读恢复，不允许新旧二进制交替写同一 Schema。卸载默认不删除状态，显式“删除本机数据”才按第 7 节执行。

## 4. 最小数据模型

### 4.1 ProductStore

`ProductStore` 的 production partition 只在发布 contract artifact 已验证、正式 transport 已配置且 Bootstrap 返回 ready identity 后打开。现有本地 Task Fixture 不写该 Store；test-only Cloud conformance 使用独立临时 partition，不能迁移、重命名或复制为 production 数据。缺少 artifact/transport 时 production bundle 在 object layer/provider 注册前失败；`signed_out`、`expired` 或 `device_registration_required` 身份只返回对应 Renderer-safe snapshot，不打开 Tenant partition，也不创建 checkpoint、Outbox 或空 projection 冒充已同步。

| 表 | 最小字段 | 关键约束 |
| --- | --- | --- |
| `store_meta` | `schema_version`, `partition_id`, `created_at`, `key_id` | 单例；partition 与打开时身份精确一致 |
| `projection_record` | `resource_type`, `resource_id`, `owner_revision`, `etag`, `payload_ciphertext`, `observed_at`, `expires_at` | PK `(resource_type, resource_id)`；owner identity 必须匹配，只能以 owner revision/ETag 的 CAS 结果替换 |
| `stream_checkpoint` | `stream_ref`, issuer/tenant/subject/device/identity revision、Gateway contract ref、`snapshot_ref`, `resume_cursor`, `observed_at` | 每个 ready identity 与事件流唯一；完整基线或单个替换事件必须与新 cursor 在同一事务提交 |
| `bundle_activation` | issuer/tenant/subject/device/identity revision、`assignment_ref/revision`, `bundle_ref`, `bundle_hash/manifest_hash`, contract/signature/trust refs、`state`, `previous_bundle_ref`, timestamps | 只激活与当前签名 identity/assignment 精确绑定且 root digest 相等的单一 bundle；组件分别校验 transport/payload hash 与 size，再按 audience/classification 加密只读存储；失败保留上一已知可用包 |
| `execution_mapping` | `mapping_id`, `engagement_ref`, `activity_ref`, `execution_ref`, Cloud owner refs、可选 `dsh_session_id`/`execution_workspace_handle`, `last_session_event_seq`, `state`, timestamps | Cloud-only Activity 不得伪造 DSH 引用；managed runtime 行必须绑定 tenant/device/execution 与精确 active bundle |
| `outbox` | `operation_id`, `idempotency_key`, `owner`, `action_kind`, `subject_ref`, `expected_revision`, `payload_ciphertext`, `state`, `attempt_count`, `next_attempt_at`, `created_at`, `updated_at` | operation/idempotency 唯一；不存 Secret/路径/完整 Cloud Task Envelope |
| `grant_projection` | `grant_handle`, `grant_revision`, `subject_ref`, `display_name`, `intents`, `expires_at`, `state`, `updated_at` | 无绝对路径；只由带 Receipt 的 Supervisor grant/revoke result 更新 |

`projection_record.payload_ciphertext` 只保存 Renderer-safe Cloud view，不保存模型消息、Artifact plaintext、原始 evidence 或 provider DTO。Cloud revision 不可比较时使用精确 ETag/opaque revision，仅做相等与冲突判断。

Material 的元数据与 Renderer-safe inline body 随 Cloud projection 生命周期加密保存；Artifact/file bytes 不进入 `projection_record`。每次 preview/download 都重新取得绑定 Material revision 的短时 access grant，Host 在 bounded staging 中校验 media type、size 与 content hash 后才暴露内容；失败、grant 到期/撤销或 staging 超期时删除临时 bytes。Cloud 的 `MaterialView.state` 仍是可用性事实，传输完成、临时缓存或用户点击 Approval 都不能把 Material、Activity 或效果标成成功。

`bundle_activation.state` 只描述包验证/切换：`staging | active | failed | revoked | rollback_required`。`execution_mapping.state` 只描述本地编排：`reserving | active | needs_reconcile | closed`，不是 Run 状态。`outbox.state` 只描述投递：`pending | in_flight | acknowledged | needs_reconcile | permanent_failure`，不是 Decision/Audit 状态。

### 4.2 SupervisorStateStore

Rust Supervisor 的显式 control runtime 已实现 schema 1 SQLite Store：`grant_ledger`、`local_receipt` 与 `operation_journal` 在副作用返回前提交，路径及 bounded result 以 AES-256-GCM 字段加密，同 operation 可跨进程重启重放；错误 key、密文篡改、外来/未知 schema 与不安全文件状态均拒绝打开。发布 sidecar 默认没有 OS Secure Store data key，因此不创建该 Store，也不声明 control capabilities；test-only conformance 仍使用 in-memory Supervisor。下表中的 `execution_claim`、Cloud receipt delivery 与 ack/reconciliation 仍是正式 artifact 接入后的 owner，不应由当前本地 Store 伪造。

| 表 | 最小字段 | 关键约束 |
| --- | --- | --- |
| `grant_ledger` | `grant_handle`, `revision`, subject binding、`canonical_path_ciphertext`, root identity/fingerprint、intents、expiry、status、timestamps | handle 永不复用；路径只在 Supervisor；每次效果重验 |
| `execution_claim` | 完整 issuer/tenant/subject/device/identity tuple、`execution_ref`, `request_id/request_hash`, idempotency/effect key、原 Gateway protocol/`contract_selection_ref`, `dispatch_hash`, session/run/step/attempt refs、lease/fencing/revision、`claim_state`, timestamps | request/hash/idempotency 冲突拒绝；side effect 前原子 claim；recovery context 保留到 Receipt ack 与审计期限结束 |
| `receipt_journal` | 完整 identity tuple、`execution_ref`, `receipt_id/request_id`, 原 Gateway protocol/`contract_selection_ref`, `dispatch_hash`, exact receipt contract/ciphertext/hash、previous hash、signature ref、effect state、`delivery_state`, timestamps | append-only terminal record；hash chain；先落盘后发送；与 claim 一起足以独立构造唯一 recovery 请求 |
| `local_receipt` | `receipt_id`, operation/session/grant refs、outcome/reason、evidence refs、timestamps | Local capability 的可读取结果；无路径/Secret/raw output |

Cloud `LocalExecutionRequestV1`/`ReceiptV1` 的精确字段仍由 Aistaff Schema 拥有。表只为 claim、恢复和投递建立索引，不定义第二 wire 类型。

## 5. 事务与跨进程流程

### 5.1 激活 Employee Bundle 与可选受管 Runtime

1. Host 读取 Cloud Workforce revision，验证 assignment 的 issuer/Tenant/Subject/Device/identity revision、audience/expiry、`bundle_hash == manifest_hash`、manifest 签名/信任链、component transport/payload hash/size、Schema、minimum client version 与 OS/arch，并在 `bundle_activation(staging)` 记录精确目标。
2. Host 只下载缺失的 content-addressed 组件，不执行源配置继承或 latest 解析。`client_mode: none` 到此即可激活展示配置；`managed_runtime` 还必须获得 Artifact admission 并让 Supervisor 建立 execution workspace/Runtime handle。
3. 所有必选组件与 Runtime readiness 通过后，Host 在一个事务中将新 bundle 置 `active`、保留 `previous_bundle_ref`，再上报 Activation Receipt。任一步失败不部分激活；撤销/kill switch 立即停止新 Activity 并进入回滚或 blocked。

SQLite 事务不跨 Cloud/Supervisor/DSH。每一步都用同一 assignment/bundle hash 幂等恢复；Cloud Release 仍是 active assignment 事实源，本地 activation 只证明该设备实际激活的包。

### 5.2 Cloud Projection

Host 先向服务端取得短时 `ProjectionSnapshotLease`，再以同一个 `snapshot_ref` 读取 Workforce/Engagement/Page；每个响应必须回显同一 `stream_ref/resume_cursor`。分页未完成前只写 staging；完整读取后在一个事务中替换当前 Cloud Projection 并提交 checkpoint，再从 cursor 之后订阅。Snapshot 过期、任一回显不一致或分页失败时整组丢弃 staging 并重开，不能混合两个切点。每个替换事件也与新 cursor 在同一事务提交。

Issuer/tenant/subject/device/identity revision 与数据库 partition 不一致立即关闭连接；资源 revision 只做相等/CAS，不按字符串大小判断新旧。Projection 损坏可隔离后按同一 snapshot lease 算法从 Cloud 重建，不能据此回滚 Cloud 或把本地旧 bundle 重新声明为 active release。

### 5.3 Approval 与用户动作 Outbox

Host 先在一个事务中写 `outbox(pending)`，再调用真实 owner。收到 owner Receipt 后，同一事务把 outbox 置 `acknowledged` 并更新对应 projection。Revision 冲突先重读；载体断开且 owner 是否接受未知时置 `needs_reconcile`，使用原 operation id 查询 Client Gateway `/operations/{operation_id}`，不自动产生第二 operation id。

无副作用、明确未送达的读取可按 backoff 重试；Decision、Grant revoke 或任何可能产生副作用的动作只能用原 idempotency key 重试，`UNKNOWN_OUTCOME` 必须先查询 owner。

### 5.4 Grant

Host 选择路径后只把它交给 Supervisor。当前 coordinator 只在 Supervisor 返回 `succeeded` Receipt 后投影 active Grant 或 revoked 状态；`failed/rejected/unknown` 只保留脱敏 Receipt，并让 `readOperation` 返回一致状态和原 operation ID 对应的 `receipt_ref`。显式 control runtime 会先以同一 operation ID 提交 `grant_ledger`/tombstone、`local_receipt` 与 `operation_journal`，再返回 Host；Host projection 失败时以该 journal 对账，不恢复 Grant。Conformance 的 Host projection 仍只在内存中，发布 sidecar 在 OS Secure Store data key 未接入时不会打开 production Store。

### 5.5 Managed execution 与 Receipt

Supervisor 在 side effect 前用完整 identity tuple、`execution_ref`、原 Gateway protocol/selection、request/dispatch hash、idempotency、lease/fencing/revision 原子写 claim。执行结束后先 append 带 exact receipt contract/hash 的 terminal `receipt_journal`，再向 Cloud 发送；发送 ack 只更新 delivery state，不改 receipt 内容。Claim 与 Receipt recovery context 保留到 Cloud ack 及适用审计期限结束，进程失联且效果不确定写 `unknown`，禁止自动再次执行。

Identity revision 变化只阻止新 offer、新 claim 和尚未发生的 effect，不能删除已 claim execution 或未投递 terminal Receipt。Supervisor 以注册设备 proof、原 claim selection 和签名 receipt hash 调用唯一 recovery-credential operation，取得绑定原 execution/effect/dispatch/receipt hash 的短时 DPoP token 后，才可提交该 Receipt 或查询接收状态；不存在第二种直接 recovery 协议。该 token 不能读取其他 Cloud 数据、续租、领取工作或重新执行。Cloud 即使因当前授权拒绝回显结果，也必须以稳定 effect/idempotency tombstone 防止再次执行。

### 5.6 DSH Session 游标

对实际由个人 Local 或 `managed_runtime` DSH 执行的 Activity，Host 消费 `session/event` 后只更新 mapping 的 `last_session_event_seq`。重连时以 DSH `session.history` 为准补齐并按 seq 幂等折叠；ProductStore 不缓存原始 events。任何将被该 DSH 模型消费的产品事实必须先追加 Session Event，成功 seq 再写 mapping 游标；Cloud-only Activity 不创建这类游标。

## 6. Schema 与迁移

AiDesktop Product/Supervisor Schema 各自使用单调整数版本、独立 SQLite `application_id` 和 `user_version`。初始化、身份检查和版本检查在 `BEGIN IMMEDIATE` 中完成；非空未版本化库、外来 application id、更新版本和未知旧版本都拒绝打开。

预发布阶段只支持显式登记的逐版本迁移：

1. 打开前验证文件 owner、partition 与加密 key handle；
2. 建立可恢复快照或原子副本；
3. 在单一事务中执行 `vN → vN+1`，更新 Schema 和 migration ledger；
4. 运行结构/外键/关键计数检查后才替换当前版本；
5. 失败回滚并保留旧库，向 UI 给出恢复/导出入口。

Projection-only 表可以清空重建；`outbox(needs_reconcile)`、active Grant、execution claim 和未投递 Receipt 不得通过“重建缓存”丢弃。跨 owner 的变更必须先部署能读旧/新语义的端口版本，再迁移本地库；不做双写兼容层。

DSH Session 升级不走 Product migration。每个 DSH 基线使用新的 Runtime Home；升级先复制验证，旧格式不兼容时保留匹配旧 adoption snapshot ref 的只读恢复入口或显式导出，不原地猜测修改 DSH 数据库。

## 7. 保留、删除与租户切换

- Cloud Projection 的 TTL 由产品/企业 policy 配置；过期只影响离线展示，在线重读 Cloud。Tenant 数据按 partition 删除，不跨租户合并。
- `acknowledged` Outbox 和已投递本地 Receipt 只有在 owner ack、reconciliation 完成且达到 policy retention 后才清理。
- `pending`、`in_flight`、`needs_reconcile`、未知效果 Receipt 和未完成 claim 永不因普通 TTL 删除。
- Grant 到期/撤销后立即拒绝访问并清除可还原路径的密文；只保留 handle、revision、时间和脱敏 Receipt tombstone 到 policy retention。
- Logout 清除内存 Token、关闭 Managed Runtime 与数据库；“退出并删除本机数据”才删除该 tenant 的加密 partition。Local 数据不随 Tenant 切换删除。
- DSH 当前无删除/retention API。V1 不直接删表；显式删除使用停止 Runtime 后移除整个目标 Session Store/Home 的产品流程，或等待上游提供正式删除 seam。

清理动作必须幂等、可审计且不追随未验证的 symlink。任何可能遗漏 unknown/未投递效果的删除都 Fail Closed。

## 8. 加密与密钥

所有真实客户数据进入 Pilot 前，ProductStore、SupervisorStateStore 和 DSH Session Store 必须具备经目标平台验证的静态加密。密钥层级为：OS Secure Store 中的设备 master handle → 每个 Local/tenant/store 的独立 data key → 数据库/字段加密；Renderer、argv、普通 env、日志和诊断包永远不接触 key bytes。

必须加密的内容包括 Cloud projection payload、Outbox payload、Session Event payload、绝对路径、Receipt/evidence 和任何客户输入。索引只保留完成查询所需的 Opaque ID、hash、状态和时间；日志与诊断再次脱敏。

当前 DSH `node:sqlite` backend 不提供静态加密，POSIX `0600` 只防止偶然读取。因此真实数据发布前必须在 SessionPersistence seam 后提供产品拥有的加密 provider，或采用经验证的 encrypted SQLite 实现；不得把 OS 全盘加密、ASAR 或隐藏目录当作完成。具体 provider 见第 10 节决策点。

密钥轮换使用新 key 写新记录、后台受限重加密和完成标记；旧 key 仅在未完成迁移时保留。密钥丢失返回不可恢复状态，不降级明文。

## 9. 损坏与恢复

| 存储 | 可恢复策略 | 禁止 |
| --- | --- | --- |
| Product Projection | 隔离损坏库，保留 Outbox/Mapping 恢复证据后从 Cloud 重建 projection | 空数组冒充无数据、丢弃 unknown Outbox |
| Session Mapping | 对照 DSH list/history、Supervisor workspace handle 和 Cloud refs 对账 | 自动创建第二 Session 掩盖冲突 |
| Supervisor Grant | Fail Closed；从 Receipt/tombstone 恢复状态，真实路径需用户重新授权 | 从 Host projection 反推路径 |
| Claim/Receipt journal | 只读隔离并停止效果；修复/导出后恢复发送 | 清空 journal 后重跑副作用 |
| DSH Session | 使用 DSH 自有 crash-tail repair；未知格式用匹配版本只读恢复 | Product 代码改 DSH events/seq |

备份与诊断不包含明文 Secret、路径、客户正文或 key。恢复结果必须明确 `ready | degraded | needs_reconcile | unrecoverable`，并提供删除、重新授权、导出或升级入口。
