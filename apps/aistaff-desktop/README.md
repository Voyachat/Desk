# AI Staff Desktop

This package wraps the DSH AI Staff web product in Electron. The renderer receives no Node or IPC bridge. The main process starts the bundled DSH CLI with Electron's embedded Node runtime and the loader's required `--expose-internals` flag, accepts only its exact `127.0.0.1` readiness line, and owns child shutdown.

On first profile creation the desktop selects the `workspace-write` permission preset and uses interactive approval for `read-only`, `workspace-write`, and `danger-full-access`; selecting full access does not disable approval prompts in this customer-facing profile. The generic DSH base keeps its unattended full-access behavior. The desktop also selects `google/gemini-3.6-flash` and registers `dashscope/qwen-plus`. Model credentials remain outside the repository and package: the main process reads `GEMINI_API_KEY` from `~/.codex/secrets/gemini.env` and prefers `DASHSCOPE_API_KEY` from `~/.codex/secrets/qwen.env`, with `QWEN_API_KEY` as a local compatibility input. Only regular owner-only files up to 64 KiB are accepted. An explicitly inherited process variable wins, and values are passed only through the DSH child environment.

Provider requests follow an explicit launch proxy or one credential-free HTTP(S) system proxy that Electron resolves identically for the Gemini and DashScope endpoints. Domain-split PAC results, a leading `DIRECT`, SOCKS, authenticated, or malformed directives are not rewritten into a global Node proxy. The child enables Node environment-proxy support while setting both `NO_PROXY` spellings to exclude `127.0.0.1` and `localhost`. Independently, the BrowserWindow resolves the Runtime URL before navigation and starts only when every returned directive is `DIRECT`; the unencrypted loopback page can never fall back through a proxy. Proxy credentials, model credentials, and raw values never enter the profile patch, command line, Renderer, or application log.

The app is installed by the repository pnpm workspace. Its local npm lock records the audited registry-only Electron and Forge dependency graph; do not install this package with npm or run a workspace install concurrently with runtime staging.

The product icon follows the [desktop packaging rule](../../docs/electron-packaging.md#product-icon).

The packaged runtime also carries the release `aistaff-desktop-supervisor` sidecar as a physical executable. Staging verifies its x86_64 Mach-O architecture, system-only dynamic libraries, executable mode, and absence of workspace paths. The current `aistaff` profile does not start its production control provider, and the sidecar receives no Store data key or control capabilities; shipping the dormant binary is not production `capability_only` activation.

Run `pnpm --filter @deepseek-ai/dsh-aistaff-desktop typecheck`, `test`, and `build` from the repository root. A release build is deliberately serial: run `pnpm --filter @deepseek-ai/dsh-aistaff-desktop stage:runtime`, restore workspace links with `pnpm install --offline`, then run `npm run make` from `apps/aistaff-desktop`. The final npm command runs the existing script only; do not run `npm install` or `npm ci`. Runtime staging uses pnpm's legacy deploy implementation, while `make` consumes only the resulting physical `aistaff-desktop-runtime/runtime` directory and produces the macOS x86_64 DMG artifact.

A packaged GUI smoke must not wait for a readiness line on the Electron main process: the main process consumes the child line internally. Treat the app as ready only when its DSH child owns a loopback listener, that URL returns HTTP 200, and a Renderer child exists. On shutdown, require the main process, Renderer, DSH child, and listener to terminate within the bounded runtime grace period.
